# Проверка критики ICO Toolkit по исходникам

Дата: 2026-09-28. База проверки: `877207db75623ff6b60567837a5ecb300e8a19fb`.
Проверены код, сохранённые отчёты и короткая контрольная проба таймаута.
Новый прогон CTF-задач не проводился.

## Что подтверждается

1. **Часть профилей узкая.** В `ico_quals_solvers.py` есть
   `WOLF_ARTIFACT_SHA256`, проверка точного хэша и константы известной задачи.
   Такие профили полезны как воспроизводимые исторические решения, но сами
   по себе не доказывают перенос на новые задачи. Это не означает, что весь
   реестр работает только по хэшам.
2. **Количество интеграций не равно числу решений.** Запуск анализатора,
   подготовленный payload и извлечённый кандидат — разные результаты.
   Долю настоящих решений нельзя вывести из числа инструментов или тестов.
3. **Общий таймаут не гарантирован на уровне реестра.**
   `ico_solver_engine.py::SolverRegistry.solve` синхронно вызывает
   `solver.solve(context)` и измеряет время после возврата. Сам реестр не
   прерывает вызов по `SolverLimits.timeout_seconds`. Отдельные решатели и
   внешние команды могут соблюдать свои лимиты, но общий механизм не
   обеспечивает жёсткую остановку. В контрольной пробе собственный тестовый
   решатель с `time.sleep(0.15)` при лимите `0.01` секунды вернулся через
   `0.155` секунды со штатным статусом, без прерывания. Проба вызывала
   реестр напрямую; это не измерение времени всего CLI и не запуск
   неизвестного challenge-бинарника.
4. **У GPT-пакета нет общего бюджета токенов.**
   `ico_solve.py::_write_gpt_handoffs` ограничивает отдельные JSON-блоки
   символами, условие — байтами, вложения — числом и размером файлов.
   Общего подсчёта токенов и ограничения готового prompt нет. Наличие ZIP
   также не означает, что все его файлы поместятся в контекст модели.

## Что в критике неточно

- Многоуровневое декодирование уже есть:
  `ico_universal_data.py::decode_text_tokens` использует очередь, контроль
  глубины и дедупликацию; поддерживает несколько кодировок. Это не полная
  реализация CyberChef Magic, но создавать второй такой движок с нуля не нужно.
- Алгоритмы не ограничиваются XOR и простым RSA: в
  `ico_universal_crypto.py` есть восстановление MT19937/LCG, RSA broadcast и
  общие простые множители. Наличие алгоритма не доказывает его достаточность
  для произвольной криптозадачи.
- Handoff уже реализован в `ico_solve.py::_write_gpt_handoffs`.
  `ico_prompt_solvers.py` отвечает за решение по тексту условия, а не за
  упаковку контекста для GPT.
- Удаление статусов `candidate` и `payload-ready` не увеличит число найденных
  флагов. Лучше сократить основной вывод до результата, доказательства и
  следующего действия, сохранив подробные статусы в отчёте.
- Внешние проверки уже проводились. Однако корпуса, по которым затем
  дорабатывался решатель, нельзя выдавать за новый независимый контроль.

## Приоритет следующих изменений

1. **Зафиксировать независимый замер.** Взять ещё не использованные задачи,
   зафиксировать commit решателя и бюджет на задачу, держать ответы отдельно.
   Считать подтверждённый флаг, ложные кандидаты и время; задачи с runtime
   проверять на разрешённых тестовых инстансах с отдельными флагами.
   После доработки не называть повтор этого корпуса слепым тестом.
2. **Сделать ограничения времени исполнимыми.** Изолировать длительные вызовы
   решателей в процессах, останавливать их по дедлайну, сохранять уже найденное
   и переходить к следующей гипотезе. Проверять также очистку дочерних процессов.
3. **Ввести бюджет GPT-пакета.** Учитывать токены готового prompt и выбранных
   текстовых фрагментов, резервировать место для ответа, ранжировать доказательства
   и явно перечислять исключённое. Текст, изображения и ZIP имеют разные
   ограничения; размер ZIP не является оценкой токенов.
4. **Улучшать повторяющиеся классы провалов.** Дорабатывать существующий граф
   преобразований и передачу производных файлов по результатам независимых
   задач. Новый инструмент или профиль добавлять под конкретный проверяемый
   пробел; число обёрток не использовать как метрику качества.

В этой поставке добавлена передача исходников для офлайн-ревью. Описанные
изменения решателя здесь не реализованы и прирост числа флагов не заявляется.
