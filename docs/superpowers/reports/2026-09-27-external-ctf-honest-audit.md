# Внешний CTF-аудит `ico-scan`

Дата: 2026-09-27. Проверка файлов и CLI выполнялась локально. Для сверки
`Average Assembly Assignment` был прочитан опубликованный helper из GitHub;
challenge-сервисы не запрашивались, бинарники задач не запускались и флаги не
отправлялись.

## Проверенные корпуса

Полный DUCTF 2024 прогон охватил 38 задач, обработал 618 файловых записей и
сохранил 342 уникальных входа. Отчёт до последнего изменения находится в
`/tmp/ico-external-ctf/ductf2024-complete-current-20260927/report.json`.

| Состояние полного прогона до последнего изменения | Задач |
| --- | ---: |
| Локальные `candidate` | 8 |
| `candidate-review` | 19 |
| `inspected-no-candidate` | 11 |
| `payload-ready` | 0 |
| `hash-verified` или подтверждены checker-ом/платформой | 0 |
| Ошибки обработки задачи | 0 |

После исходного полного отчёта отдельно проверены task-aware профили Number
Mashing, Dungeon, Vector Overflow, Rusty Vault, Adorable Encrypted Animal,
Pressing Buttons, V for Vieta, Average Assembly Assignment и sign in. Ниже —
объединённое покрытие: базовые строки взяты из полного отчёта, а статусы этих
девяти задач заменены точечными CLI-отчётами. Это не новый полный 38-задачный
прогон.

| Объединённый локальный статус | Задач |
| --- | ---: |
| `candidate` | 11 |
| `payload-ready` | 5 |
| `requires-authorized-session` | 1 |
| `candidate-review` | 13 |
| `inspected-no-candidate` | 8 |
| `hash-verified` или подтверждены checker-ом/платформой | 0 |

Одиннадцать candidate-задач: My Array Generator, Shufflebox, Three Line,
Baby's First Forensics, Bad Policies, Macro Magic, SAM I AM, Ternary Brained,
Rusty Vault, Adorable Encrypted Animal и Pressing Buttons. `candidate` — это
локально восстановленная строка, а не доказательство принятия флага.
В отчёте было 35 generic candidate-результатов, включая семь значений с
placeholder-маркерами и один шумовой результат; поэтому их нельзя считать
решёнными задачами.

До общего DUCTF-прогона был добавлен статический профиль Number Mashing.
Отдельное свежее сканирование этого каталога подтвердило `payload-ready`:
сканер распознал AArch64 `SDIV`, проверки входов и условную ветку, затем создал
`number-mashing.stdin`. Этот отчёт находится в
`/tmp/ico-external-ctf/ductf-number-mashing-final-20260927/report.json`.
Значение ввода — `-2147483648 -1`. Проверка основана на поведении ARM64:
signed `INT_MIN / -1` возвращает `INT_MIN`, а сам checker не принимает ноль и
делитель `1`. В поставленных файлах нет `flag.txt`, поэтому профиль подготовил
ввод, но не получил флаг. Этот изменённый профиль пока проверен на отдельной
задаче, не повторным полным 38-задачным прогоном.

Тринадцать задач остаются на ручной проверке: AES, Poly1305 OTM, decrypt then
eval, Kyber Decryption Oracle, Super Party Computation, ESPecially Secure Boot,
Faulty Kernel, Sheep Farm Simulator, yawa, sssshhhh, Prisoner Processor, co2 и
co2v2. Ещё восемь задач пока не
имеют локального кандидата: emuc2, pac_shell, hah_got_em, i_am_confusion,
parrot_the_emu, sniffy, waifu и zoo_feedback_form. Это граница проверенного
автоматического офлайн-анализа, а не утверждение, что задачи неразрешимы.
Статическая проверка четырёх локальных web-пакетов показывает, почему их
архивов недостаточно для реальных флагов: `hah_got_em` содержит явный
`FAKE{...}` placeholder, `parrot_the_emu` и `zoo_feedback_form` поставляются с
пустыми файлами флага, а `sniffy` задаёт `DUCTF{}` и сохраняет его в
PHP-сессии. Это не найденные флаги; для проверки динамической части нужна
авторизованная инстанция. Сервисы не запускались и не опрашивались.

Дополнительная статическая проверка `decrypt_then_eval` подтвердила, что
сохранённый пакет содержит только код: KEY и IV создаются через `os.urandom`,
а значение FLAG в исходнике — явный тестовый fallback. В архиве
`Poly1305_OTM` лежит placeholder-файл флага; runtime-ключ случайный, и выдача
MAC меняет ключ перед вычислением. Эти архивы не содержат фактическое состояние
инстанса, поэтому их тестовые значения не считаются решениями.

V for Vieta перешла в `requires-authorized-session`. Новый профиль проверяет
SHA-256 исходника, строит для каждого runtime `k` решение через второй корень
Виета и записывает самодостаточный JSON-line помощник в отчёт. Математическая
пара проверяется точным целочисленным равенством и превышает лимит 2048 бит.
Сохранённый серверный файл содержит только placeholder по умолчанию и не
содержит случайных runtime значений, поэтому локальный скан не заявляет флаг.

При попытке начать ещё один полный fast-проход промежуточный каталог вырос до
569 МБ без готового `report.json`. Запуск был остановлен при остатке 793 МиБ;
его частичные результаты не включены в статистику выше. Полный проход после
изменений остаётся непроведённой проверкой.

Для emuc2 исходный полный прогон не нашёл локального кандидата. Повторная
точечная проверка обнаружила две причины неполного evidence: TShark JSON
содержит повторяющиеся ключи `http2.header`, которые обычный JSON decoder
перезаписывал, а отдельный запуск `ico-scan` без task manifest не передавал
соседний `sslkeylogfile.txt` в профиль.

Исправленный standalone CLI-прогон на трёх сохранённых файлах задачи
расшифровал 4 TLS-потока, сохранил 6 HTTP/2 DATA тел и 8 блоков HEADERS.
Артефакт содержит `/api/login`, `/api/env`, `/api/flag` и статусы `200` и
`401`; ответ для `/api/flag` — `401`. Ни одного кандидата или подтверждённого
флага сканер не получил. Сохранённый набор не содержит успешного ответа
`/api/flag`, поэтому задача остаётся нерешённой по имеющимся файлам. Отчёт
точечного CLI-прогона: `/tmp/ico-emuc2-cli-fixed-dzp5a6t0/report/report.json`.
AES также остаётся review: опубликованный Sage-путь не подключён как
автоматический решатель.

ImaginaryCTF 2022 ранее был полностью просканирован отдельно: 13/13 задач
классифицированы, из них 8 `candidate` и 5 `payload-ready`; 0 hash/checker/
platform-confirmed. В отдельном reference-сравнении восемь кандидатов совпали
с опубликованными ответами, но этот внешний факт не повышает статус внутри
инструмента.

## Изменения

Для Average Assembly Assignment обнаружена ошибка, которую не показывал статус
`payload-ready`: генератор ссылался на `read_all_loop`, но не объявлял эту
метку. Опубликованный DUCTF helper подтверждает, что метка должна стоять перед
`INP`. Генератор исправлен; регрессионный тест проверяет точку входа цикла и
разрешение каждого перехода. Профиль `sign in` прошёл статическую проверку
хэшей бинарника и исходника, подтверждает нулевую fake-user запись и создаёт
шестишаговый сценарий для разрешённой сессии. Оба профиля не получают флаг.

В `ico_external_ctf.py` добавлены узкие профили Number Mashing, Dungeon и Vector
Overflow. Number Mashing не запускает
бинарник, ищет symbol `main`, дизассемблирует ограниченный AArch64 `.text` через
Capstone и выдаёт артефакт только при совпадении проверок на ноль, делитель
`1`, `SDIV`, сравнение результата с первым аргументом и вызовов на успешном
пути. Проверка с изменённым условием `b != 2` и фикстура со строкой `flag.txt`,
но без вызовов на успешном пути, остаются `candidate-review` и не создают ввод.

Dungeon статически разбирает таблицу комнат и callback-ы переключения дверей,
строит маршрут с двумя нажатиями и проигрывает его на модели карты. Повторное
состояние дверей фиксируется до каждого нажатия; маршрут для приложенного ELF
прошёл интеграционный тест, но отсутствующий `flag.txt` остаётся блокером.
Vector Overflow принимает только исходник с проверенным потоком управления и
non-PIE ELF, где `v` расположен сразу после 16-байтового `buf`; затем пишет
бинарный stdin, подменяющий три указателя вектора на диапазон `buf[0:5]`.
Статический путь достигает `system("/bin/sh")`, но сам флаг не извлечён.
CLI теперь исключает `likely-placeholder` и `likely-noise` из обычного списка
`CANDIDATE VALUES`, сохраняя их отдельно в отчёте и низкоприоритетном блоке.

Добавлен `ico_vforvieta.py`: он читает JSON-раунды из stdin, игнорирует текстовый
баннер, выводит проверенную пару `(a, b)` в stdout и не открывает сеть. Сканер
копирует его в отчёт и отдельно учитывает
`summary.challenge_requires_authorized_session_task_count`. Статический осмотр
веб-архивов также подтвердил, что строки вроде
`DUCTF{test_flag_real_flag_on_instance}`, `DUCTF{NOT_THE_REAL_FLAG}` и
`DUCTF{testflag}` — явно помеченные заглушки, а не локальные флаги.

## Проверки

- Три теста Number Mashing прошли: точный ARM64-шаблон выдаёт ввод, изменённый
  guard и неподтверждённый путь вывода блокируют артефакт.
- Свежий запуск `./ico-scan .../number_mashing --mode full` дал 1 задачу со
  статусом `payload-ready`, 0 флаг-кандидатов и 0 подтверждённых флагов.
- Свежий запуск Dungeon дал 1 `payload-ready`, 0 кандидатов; маршрут содержит
  561 перемещение и два переключения.
- Свежий запуск Vector Overflow дал 1 `payload-ready`; подготовлен
  `vector-overflow.stdin`, challenge-бинарник не запускался.
- Свежий CLI-прогон Vector Overflow показывает 0 actionable `CANDIDATE VALUES`;
  единственное XOR-совпадение `DUCTF{<0x16>}` сохранено только как
  `likely-noise`.
- `./verify.sh` — 252 теста прошли; smoke-проверки toolkit, Python CTF stack и
  binary stack завершились успешно.
- После добавления профилей Average Assembly Assignment и sign in повторный
  `./verify.sh` прошёл 254 теста, компиляцию Python и CLI/CTF-stack smoke checks.
  Отдельный запуск `ico-scan --mode full` для каждой задачи дал `payload-ready`,
  0 кандидатов и 0 подтверждённых флагов. Average Assembly сгенерировал
  программу со всеми объявленными branch-labels; sign in сохранил статический
  шестишаговый recipe. Отчёты: `/tmp/ico-ductf-average-assembly-cli-20260927`
  и `/tmp/ico-ductf-sign-in-cli-20260927`.
- После этого отчёта выполнен отдельный standalone CLI-прогон emuc2: 4 TLS
  потока, 6 HTTP/2 DATA тел, 8 блоков HEADERS, 0 кандидатов и 0 подтверждённых
  флагов. Полный прогон 38 задач повторно не запускался; сводная таблица выше
  остаётся объединением сохранённого полного отчёта и девяти точечных профилей.

Универсальный офлайн-сканер не может гарантировать автоматическое решение
произвольных CTF: часть задач зависит от динамического состояния сервиса,
отсутствующих файлов, специализированных математических библиотек или
интерактивного протокола. Для таких случаев отчёт сохраняет review/blocker,
вместо того чтобы объявлять случайную строку флагом.
